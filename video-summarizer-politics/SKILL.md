# 公考政治理论视频学习整理

## 使用定位

这个 skill 用于把视频内容整理成适合公考政治理论复习的学习材料。处理视频时，不只做普通摘要，而要围绕“政治理论考点、时间顺序、事件链条、政策背景、关键词和可复习结构”进行整理。

适用内容包括：
- 公考政治理论课程视频
- 时政热点解读
- 党史、新中国史、改革开放史、社会主义发展史相关视频
- 新时代中国特色社会主义思想、政府工作报告、重要会议精神讲解
- 马克思主义基本原理、中国特色社会主义理论体系、宪法与国家制度相关课程

## 工作流程

### 1. 获取视频文字

优先提取官方字幕或 CC 字幕；没有字幕时，再使用语音转文字。

下载视频或字幕：

```bash
python3 {baseDir}/scripts/download.py --url "VIDEO_URL" --output "{baseDir}/output"
```

B站视频如需登录字幕或购买权限，优先直接调用本地 Chrome 登录态：

```bash
python3 {baseDir}/scripts/bilibili_login_and_export_cookies.py --output "{baseDir}/output/bilibili-cookies.txt"
python3 {baseDir}/scripts/download.py --url "VIDEO_URL" --output "{baseDir}/output" --cookies "{baseDir}/output/bilibili-cookies.txt"
```

如果本机已安装 Chrome，登录脚本会优先直接启动本地 `chrome.exe` 打开 B站登录页，而不是走系统默认浏览器。

提取字幕文本：

```bash
python3 {baseDir}/scripts/extract_subtitles.py --input-dir "{baseDir}/output" --output "{baseDir}/output/transcript.txt"
```

### 2. 无字幕时转写音频

默认优先使用本地 Whisper 模型。只有当用户明确指定远程 API，或本地模型方案不可行时，才改用远程转写。

本地转写：

```bash
python3 {baseDir}/scripts/transcribe_audio.py \
  --provider local \
  --input "{baseDir}/output/audio.m4a" \
  --output "{baseDir}/output/transcript.txt" \
  --local-model base \
  --local-model-dir "{baseDir}/output/.models"
```

远程转写：

```bash
python3 {baseDir}/scripts/transcribe_audio.py \
  --provider remote \
  --input "{baseDir}/output/audio.m4a" \
  --output "{baseDir}/output/transcript.txt" \
  --remote-base-url "https://example.com/v1" \
  --remote-model "whisper-1"
```

远程转写时不要把密钥写进脚本或 skill 文件，而应通过环境变量传入：

```bash
set WHISPER_API_KEY=your_key_here
```

处理政治理论课程时，必须尽量保留时间信息，因为后续要按照“时间-事件-考点”建立事件链。

### 3. 本地 Whisper 模型要求

这个 skill 默认支持本地 Whisper 模型下载和缓存。使用本地转写时：
- 优先把模型缓存到工作区内部，例如 `{baseDir}/output/.models`
- 不要默认写入系统用户目录
- 模型首次下载较慢，后续可以复用
- 用户如果不想下载模型，可以明确切换到远程 API 方案

本地转写推荐依赖：

```bash
pip install faster-whisper av
```

### 4. B站登录与 cookies 使用

当 B站字幕接口提示需要登录，或者视频本身只有登录/购买用户可看时，按以下顺序处理：

1. 运行登录脚本，它会优先直接启动本地 Chrome 窗口并打开 B站登录页。
2. 用户在浏览器里完成登录。
3. 脚本读取当前浏览器中的 B站 cookies，并导出为 Netscape 格式的 `cookies.txt`。
4. 后续所有下载步骤统一优先使用这个 `cookies.txt`。

登录脚本：

```bash
python3 {baseDir}/scripts/bilibili_login_and_export_cookies.py --browser chrome --output "{baseDir}/output/bilibili-cookies.txt"
```

可选浏览器：
- `chrome`
- `edge`

注意：
- 这个脚本依赖 Python 包 `browser-cookie3`
- 在 Windows 上，脚本会优先查找并调用本地 `chrome.exe` 或 `msedge.exe`
- 如果浏览器资料目录被系统权限限制，优先在用户自己的本机终端执行
- 如果视频是付费课程，登录账号本身还必须拥有对应观看权限

## 输出原则

### 1. 转成“课程总结稿”式学习结构

视频文字整理后，默认输出为以下结构：

正文默认参考 [references/course-summary-template.md](references/course-summary-template.md)。

如果没有特殊要求，优先按该模板生成完整初稿，再根据视频内容增删局部模块。

```markdown
# 标题

> note：用 2-4 句话交代这节课讲什么、核心问题是什么、适合怎么复习、哪些内容属于二次整理。

## 思维链

> 用 1 段总述 + 1 条链式结构，先把这节课的逻辑主线交代清楚。

主线示例：
历史背景 -> 核心矛盾 -> 关键事件/会议 -> 理论结论 -> 高频考点 -> 复习抓手

```mermaid
flowchart LR
    A[背景] --> B[问题]
    B --> C[过程]
    C --> D[结论]
    D --> E[考点]
```

## 凝练版总览

> note：用 1-3 句话先概括这一节最核心的主线、结论或易错点。

### 三句话抓核心

1. ...
2. ...
3. ...

### 结构化速记

| 模块 | 一句话记忆 |
|---|---|
| ... | ... |

```mermaid
flowchart LR
    A[核心主线] --> B[阶段一]
    B --> C[阶段二]
    C --> D[阶段三]
```

> note：用 1-3 句话说明这一节的核心考点、考试价值或易混点。

## 正文

按课程总结稿方式展开，允许详尽讲解，但不照搬口语，不写成机械摘要。

## 结尾标记

> 用固定收束语提醒读者本节已结束，并点出下一步复习动作。

建议格式：
`【本节总结到此】`
`下一步复习建议：……`
```

每个知识块都应包含：
- `标题`：概括该部分讲什么，尽量使用公考政治理论常见表述。
- `note`：指出这一部分为什么重要，可能对应什么题型、考点或易错点。
- `内容`：展开解释背景、概念、事件、意义、影响和记忆线索。

另外，**每一份最终学习文档的最上方**，都应默认增加一个新的“思维链”模块，放在主标题和 note 之后、凝练版总览之前。这个模块的作用不是暴露内部推理，而是把课程内容整理成读者可见的“学习主线/理解链”，让用户一打开材料就能先抓住本节最值得背、最值得顺着理解的结构。

“思维链”必须尽量做到下面几点：
- 先用 1 段话交代“这节课到底从哪里讲到哪里”
- 再用一条可见链路写出“背景 -> 过程 -> 结论 -> 考点”或类似结构
- 最后优先补一张 Mermaid 总览图，帮助用户快速进入课程语境
- 思维链写给读者看，不写成模型提示词，不写隐含推理过程，不使用过多抽象空话

如果视频更偏“课程串讲、专题复习、阶段总结”，也要优先重组为“主线 -> 展开 -> 考点 -> 复习抓手”的课程总结稿，而不是普通摘要。

“凝练版总览”必须尽量做到下面几点：
- 先用 `三句话抓核心` 提炼本节最重要的 3 个结论
- 再用 `结构化速记` 做成简短表格，概括模块、阶段、会议、事件或易错点
- 最后优先补一张 Mermaid 总览图，用流程图、思维导图或结构图快速展示主线

总览图使用原则：
- 优先概括“总主线”，不要一上来就陷入细节
- 节点控制在够用的范围内，避免又做成一份完整正文
- 对党史、会议、政策演进、制度体系、人物事件链等内容，原则上都应给出一张总览 Mermaid 图
- 如果内容更适合结构展示，可用 `flowchart`；如果更适合归类记忆，可用 `mindmap`

### 2. 首页可加入相关图片装饰

当用户要求生成 Markdown、Word、PPT 或可视化学习材料时，首页应放一张与主题切合的图片作为装饰。

选图原则：
- 主题相关，例如人民大会堂、国旗、党史纪念馆、宪法、会议现场、城市治理、基层服务等
- 风格正式、克制，适合公考政治理论材料
- 不使用与主题无关的抽象装饰图
- 如果使用网络图片，应尽量选官方、公开、稳定来源，并在材料中注明来源

### 3. 以时间和事件为主线

公考政治理论整理时，要优先梳理“时间顺序”和“事件链条”，不要只罗列观点。

输出时应重点整理：
- 关键年份、日期、会议、文件、政策和历史节点
- 事件发生的先后顺序
- 前因、过程、结果、意义
- 事件之间的联系，例如“提出-发展-完善-落实”

推荐结构：

```markdown
## 时间线

| 时间 | 事件 | 核心内容 | 公考记忆点 |
|---|---|---|---|
| 1978年 | 改革开放启动 | 开启改革开放和社会主义现代化建设新时期 | 常与十一届三中全会联系 |

## 事件链

事件A -> 事件B -> 政策形成 -> 制度完善 -> 现实意义
```

整理事件链时，语言要体现因果关系，而不是简单堆叠：
- “由于……因此……”
- “在此基础上……”
- “这一变化推动了……”
- “其现实意义主要体现在……”

如果是课程视频，不要只写“发生了什么”，还要写清楚“老师这一段为什么这样讲、这一段在整节课里承担什么作用、考生复习时应从哪里切入”。

### 4. 根据用户提问补充对应知识点

如果用户围绕视频内容继续提问，回答时不能只复述视频，应结合公考政治理论知识体系补充相关考点。

补充时遵循：
- 先回答用户问题
- 再补充相关知识点
- 最后给出适合记忆或做题的提示

### 5. 支持表格和思维导图

当内容涉及对比、分类、时间节点、会议精神、政策措施、人物事件或易混概念时，优先整理成表格。

常用表格类型：
- 时间线表
- 事件链表
- 概念对比表
- 政策措施表
- 会议精神表
- 高频考点表

当内容层级明显、适合复习背诵时，可以使用 Mermaid 绘制思维导图。

思维导图使用原则：
- 不是每一节都强行画图，但只要内容存在明显层级、阶段划分、事件链条或知识点归类，就应补一张思维导图
- 对党史、中特、时政理论、会议精神、制度体系等内容，原则上优先提供思维导图
- 思维导图应服务于复习，不做花哨装饰，节点名称尽量简洁，突出主干和重点

除正文中的局部图示外，文档最上方的“凝练版总览”还应至少包含一张总览型 Mermaid 图。也就是说：
- 正文里的 Mermaid 图，用来解释局部知识块
- 开头的 Mermaid 图，用来先给全局框架

## 写作风格

- 语言整体改为“课程总结风格”，既像认真整理过的课后总结，也吸收博客类 skill 那种自然、连贯、像真人写的文章节奏
- 默认采用“老师讲完一节课后，帮学生系统收束内容”的口吻叙述，而不是单纯的课堂实录口吻
- 开头先搭框架，中段详细讲透，结尾明确收束
- 正文可以详尽，但每一段都要服务于“帮助复习”和“帮助理解”，不能只是把视频内容换个说法重新铺开
- 可以有引导式表达，例如“这里我们先抓主线”“这一段真正要记的是”“如果从考试角度看”“把这几步串起来就更容易理解”，但不要过度口语化
- 吸收博客风格的优点：自然衔接、重点突出、句式有变化、像人在讲清楚一件事；不要吸收博客里过强的个人感叹、营销感或闲聊感
- 不要写成机械摘要，也不要保留大量视频口语
- 对重要政治理论表述要谨慎，不随意改写规范提法
- 对时间、会议、文件、人物、政策名称要尽量准确
- 不能确认的事实应标注“待核验”

推荐的行文节奏：

1. **开头先给读者一条思维链**
2. **再用凝练版总览压缩核心记忆点**
3. **正文部分按课程逻辑详细展开**
4. **段末适度提醒“这一段要记什么”**
5. **结尾必须给出明确收束标记**

如果内容较长，优先用“自然段讲透 + 少量表格压缩 + Mermaid 抽主线”的组合方式，不要整篇都写成大段列表。

适合的表达方式：

- “这节课如果只记一句话，核心就是……”
- “先不要急着背细节，先把这条线顺下来……”
- “老师这一段其实是在解决一个更关键的问题……”
- “从课程结构看，这一部分起的是承上启下作用……”
- “如果放到考试里，这里最容易怎么命题……”
- “真正需要带走的结论是……”
- “到这里，这一节课的主线就闭合了……”

避免：

- 通篇都是“首先、其次、再次、最后”的流水账
- 每段都只写定义、意义、启示的模板句
- 像提示词一样罗列要求
- 太像会议纪要，缺少课程消化后的总结感
- 太像闲聊博客，削弱政治理论学习资料应有的正式性
- 结尾没有收束，正文突然停止

## 结尾标记要求

每份最终文档结尾都要有一个明确、肉眼可见的结束区块，用来告诉读者“本节内容已经完整收束”。默认采用下面结构：

```markdown
---

## 本节收束

> 这一节讲到这里，我们已经把“……”这条主线完整梳理完了。

【本节总结到此】

下一步复习建议：
- …
- …
```

要求：

- `【本节总结到此】` 这一类结束标记必须保留
- 收束段要简短，但要点明“本节已经讲完什么”
- 最后补 1 到 3 条下一步复习建议，帮助衔接下一节

## 重点格式

为了让学习材料更适合复习，输出时应主动标记重点内容。

推荐做法：
- 重点结论使用 `**加粗**`
- 重点提醒、易错点、常考点可用 HTML 颜色标记，例如 `<span style="color:#c62828">重点</span>`
- 大段内容之间可使用 `---` 作为横线分隔，帮助分块阅读
- 如果生成 Word、PPT 或富文本版本，也应保持“重点更醒目”的原则，可用加粗、颜色、下划线或横线分隔实现

格式使用原则：
- 不要通篇大量上色，避免页面杂乱；只突出真正高频、易错、结论性内容
- 同一份材料中，强调样式尽量统一。例如红色主要用于“重点/高频考点”，加粗主要用于“结论/定义”，横线主要用于“模块分隔”
- 如果平台不支持颜色显示，至少保留加粗和横线分隔
